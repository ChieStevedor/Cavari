# BUILD PROMPT — Poker Training App MVP

**Задача:** Побудувати MVP мобільного покерного тренажера (React Native/Expo + Supabase) так, щоб Alex отримав готовий до подання в App Store/Google Play застосунок, що генерує щомісячний підписний дохід.

**Scope — що входить:**
- Тільки турнірний формат (без кеш-треку)
- 3 тренувальні модулі: позиційні рейнджі, M/Q-ratio, постфлоп за зонами стеку
- Онбординг, платна підписка через RevenueCat, self-service видалення акаунта

**Scope — що НЕ входить (свідомо відкладено):**
- Analysis of Hands (workbook-модуль) → update 1.1
- Офлайн-режим → update 1.1
- Дата-базований spaced repetition (SM-2) → замінено на recap-в-кінці-сесії
- Діагностичний тест на онбордингу → замінено на самостійний вибір рівня
- Соціальний блок (лідерборди, друзі, виклики) → Фаза 2
- Вільнотекстовий фідбек → замінено на 👍/👎

## АРХІТЕКТУРА

**Робоча назва проєкту / bundle ID:** `poker-zone-trainer` *(тимчасова назва — фінальний бренд визначиться пізніше, для скафолдингу Expo-проєкту потрібне хоч якесь ім'я зараз)*

**Стек:** React Native (Expo) · Supabase (DB + Auth) · RevenueCat (підписки)

**Auth:** тільки email/пароль. Без соціальних логінів (знімає вимогу Sign in with Apple).

**Дані:** таблиці рейнджів і сценарії зберігаються в Supabase, НЕ в коді застосунку — виправлення без нового білда.

**Синхронізація:** застосунок вимагає інтернет-з'єднання (без офлайн-логіки в MVP). Прогрес читається/пишеться напряму в Supabase — крос-девайс синк тривіальний, без merge-конфліктів.

## КОНТЕНТ-КОНВЕЄР

1. Alex вручну кодує базові таблиці рейнджів/рішень (позиція → M-ratio → дія)
2. Скрипт-генератор рандомізує навколо базових таблиць → 150-200 унікальних сценаріїв на модуль
3. Рішення для кожного сценарію визначає детермінована формула-суддя (НЕ LLM)
4. Автоматичний валідатор-скрипт перевіряє інваріанти при кожному оновленні таблиці:
   - рейндж монотонно розширюється при зменшенні M-ratio і при пізнішій позиції
   - преміум-руки (AA-QQ, AK) ніколи не фолдяться на відкритті
   - зона Red завжди агресивніша за Green для тієї ж руки
5. Кожен сценарій отримує внутрішню мітку `confidence: verified / borderline` (border-line рука за визначенням = borderline). Мітка тільки в базі даних для Alex — юзер бачить однаковий UI незалежно від мітки.

## ПРАВИЛА (закріпити в логіці застосунку)

**Правило 1 — рівень довіри контенту:**
Сценарії з міткою `borderline` показуються юзерам нарівні з іншими, але **не рахуються в official accuracy% юзера** (виключаються з підрахунку статистики) і супроводжуються нейтральнішим формулюванням відповіді ("за цією методикою — X", а не "правильна відповідь — X"). Мітка також слугує внутрішнім фільтром для майбутнього ручного рев'ю Alex.

**Правило 2 — adaptive difficulty рахується тільки на сервері:**
Складність рівня (простий поріг: 80% правильних за останні 20 спроб → відкривається наступний рівень) обчислюється і зберігається виключно в Supabase. Клієнт ніколи не рахує рівень локально.

**Правило 3 — діагностика при онбордингу обмежена безкоштовним модулем:**
Оскільки повного діагностичного тесту немає в MVP — юзер сам обирає стартовий рівень (новачок/просунутий). Платні модулі завжди стартують з базового рівня "новачок" незалежно від вибору, складність адаптується вже всередині модуля після реальних відповідей.

**Правило 4 — 👍/👎 як сигнал, не механізм виправлення:**
Кнопка "це рішення виглядає невірним" на кожному сценарії. Поріг (напр. 3+ 👎) позначає сценарій як "потребує рев'ю" в адмін-таблиці Supabase. Це НЕ автоматично змінює контент — виправлення завжди робить Alex вручну.

**Правило 5 — recap замість spaced repetition:**
Неправильні відповіді повертаються в кінці тієї ж сесії (останні 5-10 помилок), а не за датою-планувальником.

## ФЛОУ ЗАСТОСУНКУ

1. Age-gate чекбокс "17+"
2. Реєстрація email/пароль
3. Push-дозвіл (запит одразу при першому запуску)
4. Онбординг: вибір фокусу (турнір/MTT/SNG) + самостійний вибір рівня
5. Головний екран: вибір модуля (1 повністю безкоштовний — позиційні рейнджі; 2 платні з free trial — **5 занять** на кожен платний модуль, потім hard paywall) *(число 5 — плейсхолдер, Alex уточнить на практиці)*
6. Сесія: сценарій → таймер (8-10 сек рейнджі, 15-20 сек M/Q-ratio) → відповідь → 👍/👎 опція
7. Кінець сесії: recap помилок → streak + accuracy% (загальна і по модулю; borderline-сценарії виключаються з official accuracy% — див. Правило 1)
8. Paywall після вичерпання free trial занять у платному модулі → RevenueCat checkout
9. MVP запускається тільки з англійським UI. ES і UA — окремі релізи після виходу на кожен ринок (не одночасна багатомовність). Налаштування: видалення акаунта.
